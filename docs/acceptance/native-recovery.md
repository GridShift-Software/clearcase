# Native complete case export and recovery primitives (native24)

**PREPARED / UNVERIFIED.** Library code and synthetic unit tests only. No route, real object store, D1, Worker, browser, provider or hosted run exercised it. It is not a gate PASS or native acceptance, and it changes no permission, retention or shared runtime file.

Code: `src/lib/recovery/hosted/`; tests: `tests/hosted-foundation/recovery/` (focused runner `vitest.config.ts` there; its include REPLACES the root list).

## What it does

- `exportCase(deps, {caseId, exportId, includeUserWork})` writes one case's recovery export into an injected **durable private object port**: every original's actual bytes, previews of the published version, every results package file byte-for-byte with its `VersionInfo` provenance (input revision, manifest/diagnostics/read-model digests, validator version, warning fingerprints), the publication and active-version identity, the case revision and, **only when explicitly selected**, independent user work (notes, registers, anchors) as its own blob (glossary: notes absent unless selected). Embedded originals are recorded explicitly with no invented hash.
- Authority comes first: unauthenticated, revoked, foreign or ungranted callers are refused before any byte, store read or write (a denial appends a scoped audit event). The audit record for the read is required before the first byte; an audit fault refuses. Authority and current version visibility are rechecked before the manifest commits and after the completion audit, before returning it.
- A required `VersionVisibilityPort` checks **current caller-bound per-version visibility**, independently of historical publication flags, version listings and case-level `read-preview`. Every package, preview, active pointer and published identity is checked; malformed identities fail closed. A client-invisible candidate, superseded or withdrawn identity refuses the entire mixed export with `not-found`, rather than returning a partial manifest or restoring hidden bytes. Existing case-scoped original/user-work APIs are unchanged. A fresh export with no results identities can still verify and restore independently authorized originals/user work after withdrawal; no results identity is silently removed from a retained export.
- Bytes are hashed against the asset's own metadata and listing. A missing or changed original, an unverifiable package, a case that moved mid-export or a bound breach (declared sizes, checked before reading) fails the export; there is no "partial but labelled complete".
- Blobs are written, read back, then the manifest is written **last** with put-if-absent. No manifest means no export; a repeated export id is refused (`export-exists`) and never overwrites. The manifest is canonical JSON, allow-listed (no session id, token or credential; a session id appearing in it refuses).
- `verifyExport` re-reads the stored export: pinned manifest SHA-256, strict manifest shape, accounting recomputed from entries, every blob's size and SHA-256. Missing = `export-incomplete`, differing = `export-corrupt`, wrong pin = `manifest-mismatch`, another client's manifest = `foreign-input` before any blob read. Live visibility is required before retained blob reads and again after them. Verification and restore planning recheck all read grants, revocation and visibility after their last awaited storage/target/completion-audit work, immediately before releasing metadata. Late denials append a scoped denial event.
- `planRestore` is read-only. `applyRestore` needs the exact plan hash (it includes manifest digest and the target revision), requires an **isolated target** (isolation id different from the live instance, distinct object and user-work ports, same client, empty user work), refuses a differing already-staged object before any write, takes the **pre-restore snapshot** first, stages additively (put-if-absent, resumable after a restart), verifies **every staged object including the manifest** before importing user work through `importAll` behind both fresh authority/visibility checks and the expected-revision guard, and returns per-category accounting plus invariants (objects accounted and verified, user-work rows accounted, nothing deleted or replaced). It never activates, deletes, applies retention or touches the live case. A missing, wrong-size or wrong-SHA staged readback throws `restore-failed` **before `importAll`**; additive objects and the pre-restore snapshot remain and nothing is deleted or repaired automatically. A transient read fault can be retried; actual persisted corruption remains a conflict requiring operator action. `report.ok` must still be checked for unavoidable post-import accounting failures. A late authority denial after a committed object/import/audit refuses the result but does not roll back committed data.
- Required-null object or visibility port (or a `test-standin` port under the `production` profile) is `recovery-unavailable` (503, retryable) before any authority check. There is no in-memory fallback in `src/`.

## Integration handoffs (not done here)

1. Real adapters: R2-backed `PrivateObjectPort` (client-scoped prefix, conditional put); a `PreviewCatalog` over `rs_preview` (`AssetsAccess` has no preview listing); an isolated restore target (separate D1/R2 scope and its `AsyncUserWork`, `stateRevision`).
2. `CaseOperation` has no export/restore operation. This uses `read`, `read-original`, `read-preview` and `write-user-work` on the source case. A dedicated, separately granted `case.export`/`case.restore` (like `case.upload-originals`) needs GRS-114 policy work and was not changed.
3. Supply `visibility: VersionVisibilityPort | null` to `RecoveryDeps` / `VerifyDeps` (and therefore `RestoreDeps`). Its `kind` is `current-policy` in production; `isVisible({ identity, caseId, resultsVersion }): Promise<boolean>` must consult live publication/version entitlement in the receiving client instance and return true only for the exact caller-visible identity. Do not derive it from the archived manifest, `versionsOf`, or the case-level preview grant. Policy exceptions propagate, non-true denies, null/malformed/production stand-ins refuse with 503. No live adapter or permissive default is supplied here. `versionsOf` should still filter candidates, but the recovery library no longer trusts that listing as authority.
4. Staged restore is not activation: pointer swap, publication restore and audit-chain placement belong to the publication owner.
5. Root `vitest.config.ts` include for `tests/hosted-foundation/recovery/**/*.test.ts` (coordinator-owned).
