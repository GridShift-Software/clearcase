# GRS-96: Browser viewers and manual previews for alpha file types

Decision support for [GRS-96](https://linear.app/vaper/issue/GRS-96). App base `8693ed886b7c641eacba76d06806f723f515cedb`. Sources read 15 October 2026. No app code changed, nothing built, deployed or tested in a browser. Labels: **[F]** fact from the cited primary source, **[I]** inference, **[R]** untested recommendation.

Inputs: the GRS-90 static facts (`grs-90-viewer-audit/.local/grs90-viewer-facts.md`), the accepted draft ADR 0011 on branch `grs-90-file-viewing-contract` (every accepted file viewable in the app, failed preview holds the whole update, no false citation precision), and the GRS-95 storage note at `8acba72` (workload aggregates only). No case file, `RAWS/`, production system or private screenshot was opened.

## Verdict

1. **Feasible for the alpha minimum. The recommended split keeps heavy parsing off the request path; it is a recommendation, not the only possible architecture.** Recommended: the preview-readiness work (Office conversion, email and MSG parsing, sheet extraction, archive expansion, media transcoding) runs in the operator's local processing step, which produces stored derivatives plus a manifest. A light file-delivery Worker authorizes and serves bytes from private R2. Nothing here is proven on the hosted stack or in a browser, and this note does not claim that every Worker app route only authorizes and streams. [R]
2. **The range-streaming delivery path is conditional.** GRS-95 states that ingest-time checks, write-once keys and ETag guards do not yet replace GRS-12's verify-on-load. This note therefore does not recommend streaming unverified bytes as settled. The path may be used only if it keeps the original-integrity, fail-closed guarantees and failure-injection proof shows it (see "The integrity contract"). That is unresolved design and proof work, and no new performance claim. [R]
3. **PDF and browser-native images need no derivative.** Word needs a paginated PDF rendition. Excel needs a structured sheet derivative as its interactive view; a faithful rendition may supplement it for content the grid cannot carry, never replace it. EML and MSG need a message derivative with every attachment extracted as its own fingerprinted child file. [R]
4. **Media playback: feasible but conditional.** Clients upload originals as they are; they never have to supply a playable version. Operators play files that are natively playable or transcode them to one baseline format. A file that still cannot be made playable holds the whole update (ADR 0011) until repaired. [I]
5. **Archives: feasible for ZIP only in the alpha,** through operator-side safe expansion into a manifest of child files, each previewed by its own family. Other archive formats and encrypted entries are provisional manual-repair cases, not rejected uploads. [R]
6. **Workload context:** these are source-file counts from the GRS-95 `asset` rows (1,746 files, 1,308 embedded assets, 3,054 rows), not the 1,689-document baseline: PDF 1,161 files, RFC 822 email 467, MSG 89 and "other" 13 MB in total. Word, Excel, media and archives are rare or absent in that sample. Their frequency in the 2,131-document export and in new clients is unknown. Only these aggregates are used. [F/I]

## Responsibilities

| Where | Does | Must not |
| --- | --- | --- |
| File-delivery routes of the Worker (SvelteKit on Workers) | Clerk auth and per-client authorization; map asset id → R2 key; set `Content-Type` from the recorded type, `nosniff`, a sandbox CSP and `Content-Disposition`. **Conditional on the integrity contract below:** `R2Bucket.get(key, { range, onlyIf })` streaming the `ReadableStream` body, with a `206` carrying `Content-Range`, `Accept-Ranges: bytes` and `Content-Length`. [R] | Buffer whole files (128 MB isolate memory, WebAssembly included [F S1]); convert, parse or transcode; recompute sha256 per range read. [I] |
| Browser | pdf.js for PDFs and renditions; `<img>`, `<audio>`, `<video>`; render sheet, message and archive derivatives from JSON; email HTML in a sandboxed frame without `allow-scripts` and with remote loads blocked by CSP. [R] | Parse Office binaries or MSG at view time; compute formula values. [R] |
| Operator local step (manual, 24-36 h SLA) | Clients submit originals only; the operator does the rest: download → derive → write a derivative manifest → upload derivatives → candidate import. One CLI script, not a job platform. Cloudflare Containers can host the same script later (instances from 256 MiB to 12 GiB memory [F S16]). [R] | Modify originals. Each derivative records the source sha256, tool and version, and its own sha256. [R] |

**Preview readiness is a manifest check, not a runtime discovery, and it gates candidate sign-off and publication, not client intake.** A client's upload never waits for a ready derivative. Per accepted file, record `sourceSha256`, family, status `ready | failed`, the derivative keys and hashes, and the targets: page count, sheet names and cell ranges, message and attachment ids, archive entries. Candidate import refuses sign-off while any file is `failed` or missing, and a failed preview holds the whole update (ADR 0011). Citation targets are validated against that manifest at import, so an out-of-range page is an import error and never a silent clamp (GRS-90 found clamping in the local viewer). [R]

**The integrity contract is unchanged, and the range path depends on it.** Originals stay byte-identical, keyed by sha256 (GRS-95). Derivatives sit beside them and are never offered as the original. The complete packet export still carries the originals in full; whether it also carries derivatives is an open product question (see below). GRS-95's Integrity section says the replacement of GRS-12's verify-on-load by import-time checks, write-once keys and ETag guards is not accepted. It needs a threat and failure list, a hosted failure-injection test (its P8) and the user's decision. A range read cannot re-hash a whole file per request, so range streaming of unverified bytes is not a settled design. [I] It is acceptable only if both hold: (a) whatever integrity design GRS-95 ends up accepting still fails closed for the bytes the viewer serves, with no path that returns unverified original bytes; (b) failure injection on the range route shows that corrupt, truncated and replaced objects, and a wrong ETag or `If-Range`, are refused and not served. Until then it is unresolved design and proof work. This note makes no performance or cost claim from it. [R]

## Per-family strategy

### PDF (and every PDF rendition)
- [F] pdf.js v6.4.299 (3 Oct 2026) is the latest release and is the version the app pins; Apache-2.0 [S2][S3].
- [F] pdf.js v6.4.299 uses range loading only when the response has an integer `Content-Length`, `Accept-Ranges: bytes`, `Content-Encoding` identity and a length over twice `rangeChunkSize` (default 65,536 bytes) [S4]. Otherwise it loads the whole file, which is today's behaviour for every file.
- [F] Cloudflare's default compression list does not include `application/pdf`. `Cache-Control: no-transform` from the origin disables compression [S5]. [R] Send `no-transform` on original and derivative responses anyway, so a future rule cannot break ranges or byte identity.
- [F] The API exposes `password` and `onPassword` [S4]. [I] An encrypted PDF needs a password or a decrypted private derivative. Both go through the settled password queue and manual repair.
- Fidelity: XFA forms are off by default (`enableXfa`) [F S4]. Annotations other than links are not shown today (GRS-90).

### Images
- [F] JPEG, PNG, GIF, WebP, BMP, SVG and AVIF have broad browser support; TIFF is native only in Safari; MDN does not cover HEIC [S6].
- [R] Serve native types as is. Convert TIFF (each page) and HEIC to PNG, or to a PDF for multi-page TIFF, in the operator step, and label the result as a rendition. Serve SVG only as `<img>` or in the sandboxed origin, never inline in the app DOM.

### Word (.docx, .doc, .rtf)
- [F] LibreOffice 26.8.1 is the current release, MPL-2.0 [S7][S8]. `soffice --headless --convert-to pdf --outdir DIR` converts documents. Pointing `-env:UserInstallation` at a fresh directory gives a separate profile per run [S9].
- [F] docx-preview 0.4.1 (Apache-2.0) renders DOCX to HTML and says it is "not pixel-perfect". It breaks pages only at manual breaks and at Word's `lastRenderedPageBreak` markers, which it ignores by default. It documents only `.docx` [S10]. Mammoth 1.13.0 (BSD-2-Clause) emits semantic HTML on purpose, drops visual styling and does not sanitise its output [S11].
- [R] Use a LibreOffice PDF rendition as the alpha view, shown in pdf.js and labelled "PDF rendition (LibreOffice 26.8.1) of the original". Neither HTML option gives stable pages.
- **Page identity [R]:** a rendition page number belongs to one rendition (source sha256, tool, version, fonts), not to the Word document. Store the rendition id with every page citation and show "page N of the LibreOffice 26.8.1 rendition", never "Word page N". A rendition rebuilt with another tool version or font set is a different rendition, so its page citations do not carry over unchecked. The view does not pretend the rendition's pagination equals Word's.
- **Mismatch rule [R]:** a supplied citation with a precise page is never silently downgraded to file level. If the import cannot map it to a rendition page with evidence, the candidate is held for repair. File-level citation applies only when the source supplied no precise location. A reviewer's correction of a mapping is an audited change and needs a fresh approval before publication; an earlier approval does not cover it.
- **Fidelity limit [I]:** LibreOffice's layout is not Word's. Pagination can differ when fonts are missing or substituted, so the operator machine needs the documents' fonts or metric-compatible ones. Tracked changes, comments and field results need fixture checks. **Critical unknown:** which pagination the supplied Word citations use (Word's, the source system's or none). If it is Word's, the rendition's page numbers can disagree, and the mismatch rule applies.

### Excel (.xlsx, .xlsm, .xls, .xlsb)
- [F] SheetJS CE 0.20.3 is Apache-2.0 and is distributed from cdn.sheetjs.com; the npm `xlsx` package stops at 0.18.5 [S12][S13]. Cell objects carry `v` (underlying value), `w` (formatted text), `t` (type), `f` (formula) and `F`/`D` (array and dynamic array) [S14]. Sheet keys include `!ref`, `!merges`, `!cols`/`!rows` with visibility, `!autofilter` and `!protect` [S15]. Sheet `Hidden` is 0 visible, 1 hidden, 2 very hidden, across XLSX/XLSM/XLSB/XLS [S17]. Defined names are in `Workbook.Names` [S18].
- [F] "This library will not automatically compute formula results!": values come only from the file's cached results [S19]. CE reads row and column properties only with `cellStyles`; cell styling and conditional formatting are Pro features. CE decrypts only XOR-encrypted XLS and throws on other encryption [S20].
- [R] In the operator step, parse with SheetJS (`cellFormula`, `cellNF`, `cellStyles`, `cellDates` off so serials stay as stored) into a per-sheet JSON derivative: every non-empty cell with `v`, `w`, `t`, `f`, the merges, row and column visibility, sheet order and `Hidden` state, and defined names. The browser shows read-only sheet tabs and a searchable virtualized grid with the full value and formula in a cell detail panel. Cite targets as `sheet!A1:B9`, validated against `!ref`.
- **Fidelity limits [I]:** (a) A formula with no cached value shows the formula and "no stored value", never a computed one. (b) Hidden and very-hidden sheets, rows and columns are present and labelled; whether they appear by default is a user choice. (c) CE does not carry fills, fonts, conditional formats or charts. The grid keeps values and structure, but that does not prove the workbook's visual content is completely covered where charts, formatting or comments carry meaning (this note did not check CE's comment support). Treat these as fidelity gaps: fixture-check each, then supplement the grid with an appropriate faithful preview (for example a labelled LibreOffice rendition of the affected sheets) or manual repair, and keep the interactive grid. A value-only extract does not replace the complete-viewing requirement. (d) Encrypted workbooks are provisional manual repair. (e) Pivot caches and external links show only their stored values.
- [I] ExcelJS 4.4.0 (MIT) was last published in October 2023, so it is not the first choice. Converting a whole workbook to PDF flattens it and breaks ADR 0011, so a PDF rendition can supplement the grid but not replace it.

### Email: EML and MSG
- [F] postal-mime 4.0.7 (MIT-0) runs in browsers, Bun and Cloudflare Workers. It returns ordered headers including raw lines, the addresses, `text`, `html` and attachments with `disposition`, `related`, `contentId` and content. It does not sanitise HTML. It holds the whole message in memory and has default limits (nesting 256, headers 2 MB, 10,000 parts, nested RFC 822 depth 10, after which `rfc822DepthExceeded` is set) [S21][S22].
- [F] @kenjiuno/msgreader 1.29.0 (Apache-2.0) reads MSG transport headers, the plain body, recipients, timestamps, attachments as bytes and the compressed RTF body. Its README does not mention HTML bodies or embedded `.msg` attachments [S23][S22]. @kenjiuno/decompressrtf 0.1.4 (BSD-2-Clause) was last published in 2021 [S22].
- [R] Build a message derivative in the operator step: headers (raw lines kept), a body view, and an attachment list. Extract each attachment as a child file with its own sha256, MIME type and its own preview through the matching family. Nested messages recurse up to a stated depth. This closes the GRS-90 gap of unfingerprinted embedded attachments. Render HTML in a sandboxed frame, with `cid:` images rewritten to child-file URLs, and block remote images (tracking) and scripts. Show the plain-text part next to it.
- **Fidelity limits [I]:** an MSG that was never sent has no transport headers, so show MAPI fields under a label. An RTF-only or RTF-encapsulated HTML body needs decompression and de-encapsulation, so show plain text with a label until fixtures prove that path. Calendar items, TNEF (`winmail.dat`) and S/MIME-signed or encrypted parts are manual-repair cases. Citations target `message` or `attachment:<child id>`; anything else is file-level.

### Audio and video
- [F] MDN recommends MP4 with H.264 video and AAC audio as the combination every major browser supports. H.264 and AAC are patent-encumbered, and Firefox uses the OS codecs for them. VP8, VP9 and AV1 are royalty-free. HEVC support depends on hardware, OS and an extension. MDN calls QuickTime MOV unsupported outside old Safari [S24][S25]. Opus in Ogg reached Safari only in 18.4 [S24]. AMR plays in neither Chrome (outside ChromeOS) nor Firefox, and MDN leaves Safari undetermined [S26].
- [F] FFmpeg 9.0.2 (18 Sep 2026) is the latest stable release. It is LGPL-2.1+ unless built with `--enable-gpl` or `--enable-nonfree`, and its legal page warns that codec patents may apply [S27][S28].
- [R] Clients upload the original; no client-ready derivative is required. Play the original when its container and codec are in the baseline. Otherwise the operator transcodes to MP4/H.264/AAC, or WebM/VP9/Opus if patent licensing rules out H.264, and labels the result as a rendition. Seeking needs a `206` range path, which is conditional on the integrity contract above. Cloudflare Stream is not needed at alpha scale.
- **Not proven:** iOS Safari seeking through a Worker-built `206`; long files; variable-frame-rate or rotated phone video; multi-track audio. MDN's tables document support. They are not test results for these browsers.

### Archives
- [F] ZIP APPNOTE 6.3.9: names "MUST NOT contain a drive or device letter, or a leading slash", use `/`. Bit 11 marks UTF-8 names, bit 0 marks encryption, ZIP64 is allowed at any size, and every entry carries a CRC-32 [S29].
- [R] Expansion in the operator step only, with no execution and nothing written outside a scratch directory. Reject or flag: absolute paths, `..` segments, drive letters, symlinks, duplicate names after normalization, and encrypted entries. Set limits on entry count, total and per-entry expanded size, compression ratio and nesting depth, and hold the update when a limit trips. Record per entry: the raw and decoded name, the sizes, the stored and verified CRC-32, the sha256, and the child asset id. Each child is a contained file with its own identity and family preview; the archive original stays byte-identical. The browser shows a folder tree from the manifest.
- [F] fflate 0.8.3 (MIT) and @zip.js/zip.js 2.23.0 (BSD-3-Clause) are maintained JS ZIP libraries [S22][S30]. [I] Either can run the expansion under Bun. 7z, RAR and TAR variants need a different tool, whose license was not checked here, so they are provisional manual-repair cases for the alpha, not rejected uploads.

## R2, Worker and cost constraints
- [F] Workers set no response-size limit and no wall-clock limit on HTTP requests. CPU is 10 ms per request on Free and up to 5 min on Paid; memory is 128 MB per isolate; uploads are capped at 100 MB on Free and Pro plans [S1]. R2 egress is free; Class B costs $0.36 per million with 10 M free per month; storage costs $0.015 per GB-month with 10 GB-month free [S31]. Presigned URLs work only on the S3 endpoint, not on custom domains (GRS-95).
- [I] Each ranged `get()` is presumably one `GetObject`, billed as Class B; the pricing page does not say. At pdf.js's 64 KiB chunks, reading all of the largest v5 original (258,590,305 bytes) would take about 3,946 requests. That is arithmetic, not a measurement, and it holds only if the conditional range path above is adopted. It is not a performance claim. Raising `rangeChunkSize` cuts it. Derivatives add storage roughly proportional to Office, media and archive volume, which is small at v5.
- [R] Serve originals and derivatives from a separate hostname (a Worker route) with the sandbox CSP, as the second loopback origin does today. Do not hand presigned S3 URLs to the viewer: they bypass Clerk authorization and the CSP.

## Product questions for the user
Settled inputs given by the parent task, not asked again (their source decisions were not re-read here): generated views of each accepted file, the password queue for encrypted files, no external tracking (email remote content stays blocked) and no invented values (formulas without a cached value show "no stored value").

Open, in priority order. Recommendations are open until the user decides:
1. **Word citations.** Should page citations to Word files refer to the labelled LibreOffice rendition's pages (recommended, with the mismatch rule above), and what pagination do the supplied Word citations use?
2. **Hidden workbook content.** Show hidden and very-hidden sheets, rows and columns with a label (recommended), or hide them by default?
3. **Export packet.** Does the complete packet carry the generated derivatives and manifest next to the originals, or the originals only? The originals are carried in full either way.

Provisional recommendations that stay open to repair rather than to refusal:
- **Spreadsheet fidelity gaps** (charts, formatting, comments): fixture-check, then supplement with a faithful preview or manual repair. The grid stays.
- **MSG with an RTF-only body:** publish only with a labelled plain-text view until fixtures prove the RTF path, or repair by hand.
- **Media, non-ZIP archives, calendar items, TNEF and S/MIME parts:** operator transcode or expansion where possible, otherwise manual repair. The upload is accepted in every case; the update waits.
- **Baseline media format:** MP4/H.264/AAC, or WebM/VP9/Opus if patent licensing rules out H.264. This is part of the software audit below.

## Probes still needed (synthetic fixtures only)
- **Fixtures:** DOCX with missing fonts, tracked changes, comments and fields; `.doc`. XLSX with formulas lacking cached values, hidden and very-hidden sheets, merges, dates, more than 100k cells, XLS. EML with nested RFC 822, `cid:` images, non-UTF-8 charsets. MSG with RTF-only and HTML-in-RTF bodies, an embedded MSG, no transport headers. ZIP with traversal names, a zip bomb, an encrypted entry, CP437 names, a nested ZIP. MP4, MOV/HEVC, WebM, WAV, M4A, AMR.
- **Desktop and mobile:** Chrome, Firefox and Safari on desktop, iOS Safari and Android Chrome. Check pdf.js memory on the largest synthetic PDF, grid search on a large sheet, and media seeking.
- **Hosted:** a Worker range route on R2 (`206`, `If-Range`/ETag, `no-transform`), pdf.js range loading against it, and observed Class B counts. Run it only after GRS-95's integrity design exists, and include failure injection (corrupt, truncate, replace, wrong ETag) that shows the route refuses unverified bytes.
