# Verify hosted isolation, recovery and release readiness

Planning key `CC-20`. Phase V2. Milestone `M5`. Type gate.

## Outcome

A reviewer can prove the complete client/operator workflow in staging and assess a concrete release candidate.

## Dependencies

[GRS-31](https://linear.app/vaper/issue/GRS-31/sign-off-and-publish-an-exact-results-version)

## Write scope

- `tests/e2e/hosted/**`

- `scripts/verify/hosted/**`

- `docs/acceptance/hosted/**`

- `docs/operations.md`

## Acceptance

- [ ] Run client upload, notification sink, operator download, manual package import, private preview, sign-off and client view with controlled data.

- [ ] Test two client instances, admin/client roles, unauthenticated requests, direct draft-asset URLs, stale sessions and wrong-case/version identifiers.

- [ ] Exercise upload/import/publish retry, backing-store loss and restore, interrupted processes and rollback. Confirm the published version and user work survive recovery.

- [ ] Reconcile authorization, performance, audit, support entry points, documentation and remaining risks at the exact release revision. Produce a deployable candidate; live deployment remains a separate authorized action.

- [ ] Assign a second independent reviewer for any verification code written by this gate owner. The author cannot approve their own acceptance suite or final verdict.

- [ ] Prove the complete workflow using a fresh controlled submission that is not either parity fixture. Follow the documented manual recipe to produce every required dataset and original/citation mapping, import and review that exact input/results version, publish it and verify the client view. Existing sample imports and one Markdown risk round trip alone cannot satisfy this criterion.

- [ ] Re-run hosted-foundation scenarios for provisioning, concurrent edits, session revocation, user-work identity across replacement publication and rollback, sign-in recovery and logged-out support/information access. Record BA-19/BA-20 evidence or HOLD; automation stays deferred.

## Verification

Report PASS, HOLD or FAIL at the exact reviewed revision. Include commands, exit codes and artifact paths. A skipped check is not a pass. Read the local delivery plan and orchestration protocol before dispatch.

Use an independent reviewer for a gate. For discovery or design, verify the cited source or probe and record unresolved choices. Later-phase implementation requires a concrete test recipe before dispatch.

Metric: End-to-end completion, recovery time, cold and warm hosted latency. Budget: Pass the CC-15 budgets with measured receipts. No release on blocked isolation, publication or restore evidence.

## Boundaries

Keep RAWS and current production read-only. Do not commit case documents, extracted text or secrets. No Cursor agents; every Opus agent uses high effort. Only the coordinator updates Linear. No deployment, production publication or external messages under this issue without the appropriate execution authority.

## Handoff

Return the branch/worktree, base and head revision, changed paths, accepted criteria, failed or skipped checks, evidence paths and proposed follow-ups. Do not mark the issue Done yourself.
