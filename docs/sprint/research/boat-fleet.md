## 1. Verified facts (where the homepage was loose, the docs win)
- Ubuntu 24.04 VMs, per-second billing while running, stopped costs nothing. Sizes: `small` 2 vCPU/4 GB $0.018/h, `default` 4/8 $0.036, `large` 8/16 $0.072, `xlarge` 16/32 $0.200 ($100 plan only). Disk 51/51/111/251 GB. https://docs.boat.dev/pricing.md, https://docs.boat.dev/machines.md
- Plans: $20/mo per seat gives 100 concurrent sandboxes, **12/60/200 starts per minute/hour/day**, 555 h of `default` time, 10 saved snapshots. An organisation multiplies all of these by seats. Overage $0.036/h; extra saved snapshots $0.056/day. Egress free. https://docs.boat.dev/limits.md, https://docs.boat.dev/organizations.md
- Trial: 7 days, 25 h total, 2 concurrent, `small`/`default` only, TTL ≤ 2 h, **no saved snapshots and no `large`**. The golden-snapshot design needs the first payment, so press "Upgrade now" on day one. https://docs.boat.dev/free-trial.md
- Regions: EU only (Germany, Finland, France); there is **no region field** on create. Snapshot copies "can be stored outside the EU". SOC 2 in progress, not certified. https://docs.boat.dev/compliance.md, https://docs.boat.dev/api/reference/sandboxes/create-sandbox.md
- Image: Node 24.18, **Bun 1.3.14 (we need 1.4.2, install it)**, Google Chrome 151, git, gh, Docker. No Playwright. https://docs.boat.dev/machines/tools.md
- TTL default 1 h from start or resume (not idle), max 30 days; **a fork does not inherit the source TTL**. `boat extend ID --hours N`. https://docs.boat.dev/long-running-tasks/auto-stop.md
- `boat exec` waits 30 s by default, max 600; `--timeout 0` streams with no limit and exits with the command's code; `--detach` returns a pid for `--status/--attach/--kill`. https://docs.boat.dev/long-running-tasks/background-commands.md
- Snapshots every minute and at stop; `boat snapshot ID NAME` saves a named one, `boat new --from NAME [--count N]` deploys it, "ready in a few seconds, whatever the size of the disk", files hydrate in the background (`hydrated: true`). `~/.cache` and `/tmp` are **not** saved. Don't template by forking a stopped sandbox; save a name. https://docs.boat.dev/snapshots.md, https://docs.boat.dev/snapshots/whats-saved.md, https://docs.boat.dev/snapshots/templates.md, https://docs.boat.dev/readiness.md
- Fork of a running source may miss the last minute of writes; stop first. https://docs.boat.dev/snapshots/resume-and-fork.md
- `boat run --from NAME --type SIZE --push DIR -- CMD` creates, copies the checkout in, runs, prints cost, deletes, exits with the command's code. https://docs.boat.dev/ci.md, https://docs.boat.dev/cli-reference.md
- API keys: `boat api-key create NAME --preset read-only|full-sandbox|ci|admin --ttl 90d`; secret shown once; an account key acts as its creator; `ci` = operate plus create/resume/fork/delete-own. https://docs.boat.dev/api-keys/scopes.md
- Environments carry repos (`boat env add-repo base OWNER/REPO --branch B`, cloned to `/home/user/<repo>`), vars and secret files; a saved snapshot does **not** inherit an environment (`--environment NAME` or `--no-env`); `--safe-for-third-parties true` passes nothing from the account. https://docs.boat.dev/environments.md, https://docs.boat.dev/environments/access.md
- Public URL: `boat host ID PORT [--private|--public|--localhost]` → `https://<sub>-<port>.on.boat.dev` with a `_token` by default. `boat forward ID --remote P --local Q` for a tunnel. `boat desktop ID` streams 1080p60; `boat browser ID` Chrome only. https://docs.boat.dev/hosting.md, https://docs.boat.dev/ssh-access.md, https://docs.boat.dev/desktop-streaming.md
- Agents inside: `boat prompt ID --provider claude|codex "…"` after connecting a Claude or ChatGPT subscription in Agents & Proxying; a running prompt extends the TTL. https://docs.boat.dev/integrated-agents.md, https://docs.boat.dev/integrated-agents/keys.md
- Retention: command history 90 days, stopped disks 14 days; `--no-monitoring`, `--no-snapshots`, `boat data-retention enable` (ZDR). Idempotency-Key on create and fork. https://docs.boat.dev/data-retention.md, https://docs.boat.dev/api/v1.md
- Local agents: `claude mcp add --transport http boat-docs --scope user https://docs.boat.dev/mcp`; always pass the sandbox id, never `current`, in scripts. https://docs.boat.dev/ai-tools.md

## 2. The golden snapshot `clearcase-golden`
Build script (design, `scripts/boat/build-golden.sh`, run by the owner or one agent, about 15 min): `boat new --type large --ttl 3600 --environment clearcase-ci --json` → in the sandbox, `cd /home/user/clearcase` (cloned by the environment at `sprint/hosted-demo-20261105`), install Bun 1.4.2 (`curl -fsSL https://bun.sh/install | bash -s "bun-v1.4.2"`), `bun install --frozen-lockfile`, `bunx svelte-kit sync`, `bun run --bun build`, `bun run --bun build:hosted` (Wrangler 4.151.1 under Node 24, warms its cache), `bun run --bun fixtures:generate` (synthetic), run one small vitest file to warm `node_modules/.vite`, set `CLEARCASE_CHROMIUM=/usr/bin/google-chrome-stable` in `~/.bashrc` (Chrome 151 is already there; if a pinned Chromium is wanted, install it under `/home/user/browsers`, never `~/.cache`), write `/home/user/clearcase/.boat-golden.json` `{sha, bunLockSha256, bun, chrome, builtAt}`. Then `boat stop ID`, poll to `stopped`, `boat snapshot ID clearcase-golden`, `boat delete ID --yes`.
- **No v5 and no secrets in the golden snapshot.** It is copied to every fork, may be stored outside the EU, and an org-shared name only strips logins, not files. v5 goes into a single developer's fork for one run (see risks).
- Refresh: nightly by cron on the owner's box, and whenever `bun.lock`, `packageManager`, Wrangler or Chrome changes; `run-checks.sh` compares `bunLockSha256` with the PR's `bun.lock` and falls back to `bun install --frozen-lockfile` in the fork (about 1 to 2 min slower) while printing "golden is stale". Re-saving under the same name replaces the old copy; running sandboxes are unaffected. Keep a dated name too (`clearcase-golden-20261028`) for rollback; two names count 2 of the 10 free.
- Boot: a few seconds to `ready`; first `bun`/`vitest` is slower until `hydrated`; the playbook learns the hot files after the first run from a fresh save.

## 3. Usage patterns and cost per run
(a) **PR check, sharded.** `boat new --from clearcase-golden --type large --ttl 2400 --count 5 --json` (5 starts); forks 1–4 run `bunx vitest run --shard=i/4 --reporter=junit --outputFile=/home/user/out/junit-i.xml --maxWorkers=6`, fork 5 runs `bun run --bun check && bun run --bun build`. Assuming the whole suite takes about 25 min at 2 workers, each shard on 8 vCPU is about 6 to 8 min; check and build about 10 min. Compute ≈ 4 × 8 min of `large` + 10 min `default` ≈ 1.2 `default`-hours ≈ **$0.045 per PR**, wall time about 10 min. Measure on the first run and recompute.
(b) **Browser journeys against staging from a fork.** `boat new --from clearcase-golden --type default --ttl 1800`, `boat exec ID --cwd clearcase --timeout 0 -- bash -lc 'CLEARCASE_CHROMIUM=/usr/bin/google-chrome-stable bun tests/e2e/pilot/run.mjs'` or an Astra script pointed at the staging URL. `unshare -rn` works in the VM (full kernel, sudo). Cost about $0.006 per 10 min. **An EU fork sees 20 to 40 ms to a London-pinned Worker; South Africa sees 150 to 200 ms**, so the Monday speed gate (2 s pages, 3 s PDF) is still measured from a South African vantage point; boat gives functional coverage and "no 401/503" only.
(c) **Exploratory Astra on the local app.** `boat exec ID --cwd clearcase --detach "PORT=41101 bun run --bun start"`, then `boat host ID 41101 --localhost --private --title "PR 123"` (the app binds 127.0.0.1, hence `--localhost`; the token URL is a password, share it in Linear only) or `boat forward ID --remote 41101 --local 41101` for a tunnel, `boat desktop ID` to watch Chrome. The originals site uses `*.localhost:41102` host matching, which the public URL cannot carry; use the tunnel for PDF checks. Cost $0.036/h; TTL 2 h.
(d) **Agents inside boat (`boat prompt`) versus agents local.** Inside works (Claude Code and Codex are preinstalled, subscription sign-in once, conversations survive stop and fork) but it bypasses T3 Code, Linear tooling, our skills and the leak-scan hook, and puts the owner's subscription token on every sandbox. **This week: agents stay local in T3; boat is compute only.** Revisit `boat prompt` for parallel Lows after the demo.

## 4. Integration: `scripts/boat/run-checks.sh` (design only)
Interface: `scripts/boat/run-checks.sh [--sha HEAD] [--shards 4] [--snapshot clearcase-golden] [--type large] [--only test|check|build|e2e] [--out .local/boat/<sha>]`. Exit 0 pass, 1 a check failed, 2 infrastructure (no key, `429 rate_limited`, `503 out_of_capacity`), never silently skipped.
Steps: (1) `boat login --key-stdin --json <<< "$BOAT_API_KEY"` from the developer's keychain or T3 `request_secret`; `boat limits --json` and refuse if `canStart` is false. (2) `git bundle create /tmp/pr.bundle <golden sha>..<sha>` so unpushed commits work without a GitHub token in the sandbox. (3) Create N+1 sandboxes from the snapshot with `--count`, `--ttl 2400`, `--no-monitoring`, `-e CLEARCASE_CHROMIUM=…`; record ids to `$OUT/sandboxes.txt`; `trap` deletes them on any exit. (4) `boat scp` the bundle in, `git fetch /home/user/pr.bundle && git checkout --detach <sha>`; if `bun.lock` differs from `.boat-golden.json`, `bun install --frozen-lockfile`. (5) Run shards and the check/build sandbox in parallel with `boat exec --timeout 0 --cwd clearcase -- bash -lc …`, capturing exit codes. (6) `boat scp` JUnit and `check.log` out, merge to `$OUT/summary.json` `{sha, shards, passed, failed, durations, cost}` with cost from `boat usage ID --json`. (7) `boat delete ID --yes` for every id. The agent reads `summary.json` and quotes the SHA and exit code in its report.
- **Key:** each developer creates their own `boat api-key create t3-<name> --preset ci --ttl 90d` (an account key acts as its creator; `ci` can delete only sandboxes it created). Store it in the OS keychain or T3 secrets, never in the repo or `.local` plaintext.
- **Secrets:** none needed for vitest, check or build. Staging journeys need the Clerk dev test user and the staging URL only; pass them with `-e` at create (per-sandbox vars travel into forks but not into saved snapshots we make from a fresh sandbox). Cloudflare and Clerk secret keys never go to boat.
- **TTL and cleanup:** every sandbox gets `--ttl`; the trap deletes; a nightly `boat list --filter r --json` sweep deletes anything older than 3 h; `boat run` for ad-hoc one-shots deletes itself.
- **Monthly cost, 3 developers × 15 PRs/day, 22 days ≈ 1,000 runs:** about 1,200 `default`-hours plus 225 starts a day. One $20 seat includes 555 h and 200 starts/day, so it overruns both. **A 3-seat organisation at $20 = $60/month** includes 1,665 h and 600 starts/day; expected overage $0. Patterns (b) and (c) add under $5. Cap: keep the wallet at $0 (starts then fail with `402 billing_required` rather than spend) until usage is known, no auto top-up.

## 5. Risks and the owner's setup
- **Data boundary.** Sandboxes are EU VMs, snapshot copies may leave the EU, command output is retained 90 days, SOC 2 is pending, and there is no DPA on the docs. Synthetic by default everywhere. v5 only when a check needs it, in one sandbox created with `--no-snapshots --no-monitoring`, data copied in by `boat scp` from the owner's `.local`, deleted the same hour; never in a saved snapshot, never in a hosted URL. Confirm with the client before v5 touches boat at all; the owner's permission covers Cloudflare sandboxes, not a third vendor.
- **Credentials.** With a repo in the environment the owner's GitHub token lands in every sandbox; prefer a fine-grained read-only token on the `clearcase-ci` environment or the bundle route above. Org-shared snapshots strip the saver's logins but keep files, so the golden build must never write secrets to disk. Rotate the `ci` keys with `boat api-key rotate` at 90 days.
- **Networking.** First outbound connection may fail in the first second (retry); `409 sandbox_starting` for up to 60 s; the IP changes on every resume and fork; `--fail-fast` to avoid waiting on capacity; `Idempotency-Key` on create and fork so retries don't double-bill.
- **Cost cap.** Starts, not dollars, are the first wall (200/day/seat). Watch `boat limits`; empty wallet is a hard stop by design.
- **Setup, in order (owner, about an hour):** 1 `curl -fsSL https://boat.dev/install | sh`, sign in with GitHub, choose "for me", take the $20 plan and press **Upgrade now** (the trial blocks saved snapshots and `large`). 2 `boat org create gridshift`, invite the two developers, 3 seats. 3 Dashboard → Environment → Connect GitHub; `boat env add-repo clearcase-ci GridShift-Software/clearcase --branch sprint/hosted-demo-20261105`; `boat env set clearcase-ci --secrets false --agents-credentials false --boat-credentials false`. 4 Each developer: `boat api-key create t3-<name> --preset ci --ttl 90d` into their keychain. 5 Build `clearcase-golden` with the script in section 2 and `boat --org gridshift snapshot …` so all seats can deploy it. 6 Add the boat-docs MCP to Claude Code and Codex. 7 First `run-checks.sh` on the sprint head, record the measured shard times, and set `--shards` from them.
