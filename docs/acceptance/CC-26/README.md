## Reproduce the review

Use a clean checkout at the `dev` merge commit of the `wave/proofs-fixes` PR (its SHA is recorded on GRS-27). Run `scripts/agent-tools/doctor` first. Before the commands expected to exit 0, run `bun install --frozen-lockfile` in the repository root and in each independent probe workspace: `tests/hosting-probe/{runtime,deployment,identity,storage,notifications}`. The recovery probe has no separate lockfile or dependencies; it uses the storage workspace's frozen install. Each command below expects **exit 0** on a passing local input check; any other exit is a FAIL or HOLD with its output and artifact path recorded. Run the five ancestor-aware evidence checks in the [proof ledger](../hosting/index.md#proof-ledger); expect exit 0. Rerun the runtime probe at the review SHA and check its new `.local/hosting-probe/runtime/summary.json`; expect exit 0 for both commands. Checking the committed runtime summary at a later HEAD instead returns exit 1 by design. The final integrated runtime rerun and its exact-revision receipt remain an integration-owner dependency, not a reason to rewrite the committed summary. Keep its original `sourceSha` unchanged. A local rerun does not create committed exact-SHA evidence for the integrated gate. For this docs packet, `bun run --bun check` and `bun run --bun test` expect exit 0; the planning check is `scripts/agent-tools/check-plan` with the configured Linear readback, as described in [development](../../development.md#toolchain-and-commands). A planning readback failure is not waived by this packet.

At the integrated implementation SHA, run `bun run --bun gate` and `bun run --bun gate:hosted`; both expect exit 0 and an exact-SHA `GATE PASS` summary. The hosted summary must name each real boundary or double. Its current local fixture uses identity, store, asset and audit doubles, so a local PASS cannot discharge production Clerk, remote D1/R2, email or deployment. [Hosted checks](../../development.md#hosted-checks-grs-138), [hosted verification skill](../../../.agents/skills/verify-clearcase-hosted/SKILL.md).

The user must run `.agents/skills/verify-clearcase-hosted/bin/verify-clearcase-hosted run` once at the checkpoint on the integrated revision. Expect exit 0 and a run directory with `summary.json`, `drive.json`, screenshots and a verified synthetic original download. An exit 3 is a skipped preflight, not a PASS. The user also signs off on the aggregate evidence. Only then may GRS-36 proceed beyond its already approved local bootstrap. [Skill run contract](../../../.agents/skills/verify-clearcase-hosted/SKILL.md#launch), [GRS-27 decision](../../plan/tickets/CC-26.md#user-decision--19-october-2026).

The user reviews the aggregate evidence, runs the verification skill once and signs off at this checkpoint. A wave PR holds at most seven tickets; Greptile's check, CI and zero unresolved findings gate its merge into `dev`. The external reviewer approves only a release PR from `dev` into `main`; the user alone merges `main`. Allow one written fix round and one re-request. Routine updates run at 08:30 SAST on weekdays.
