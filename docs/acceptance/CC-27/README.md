From a fresh checkout or worktree of the reviewed head on `puk`:

```sh
git rev-parse HEAD

  bash docs/acceptance/CC-27/rerun.sh; echo exit=$?
```

The clone must contain the pinned pstack revision from `scripts/agent-tools/skills.lock.json`; `.local/` is ignored. `rerun.sh` runs every step below in `env -i HOME=$HOME PATH=/usr/local/bin:/usr/bin:/bin bash --noprofile --norc`, with `CLEARCASE_BUN` set to `CC27_BUN`, by default the bun on the caller's PATH. The doctor requires Bun, and on `puk` it lives in `~/.local/bin`, outside that PATH. It creates and removes a throwaway detached worktree for item 6. It first deletes the outputs of an earlier run in `CC27_OUT`, so an old receipt cannot pass as new evidence. It exits 2 instead if `CC27_OUT` holds `receipts/` or `transcripts/` that `rerun.sh` did not write. Then it writes `summary.tsv`, `revision.txt`, `identity-audit.txt`, `transcripts/` and `receipts/` under `CC27_OUT`. It exits 1 if any step's exit code differs from the expectation, if `git status` of the throwaway worktree fails, or if the identity audit finds a receipt that names another head or a PASS receipt without a base, a merge base and a working tree Git reported clean. It exits 2 if it cannot read the revision and status of the checkout it tests. Without `CC27_READBACK` the Linear steps, and without `CC27_PSTACK_CHECKOUT` the pstack comparisons, are SKIPPED, and the run exits 3 (INCOMPLETE) instead of 0. If the export changes, `v3-description-drift` may return 0 (no drift) instead of 1. Set `CC27_EXPORT_EXPECT` accordingly and read the transcript.
