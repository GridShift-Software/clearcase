# View data contracts for the hosted-demo slices

Research only, sprint worktree `sprint/hosted-demo-20261105` at `21dfb2b7`, 28 October 2026. Read every loader under `src/routes/v/[vid]/`, the helpers they call, `src/lib/server/runtime/contracts.ts` and `src/lib/user-work/hosted/d1-user-work.ts`. Sizes come from `.local/astra/recovery-local/data/results.sqlite` (v5, 1,689 documents): byte lengths and key names only, no values. Nothing was run, edited or deployed.

**v5 measurements.** `version.chronology_json` (the `ChronologyListRow[]` every document-row view parses) is 1.51 MB, about 890 B per row. Per document, `row_json` averages 900 B, `state_json` 360 B, `attachments_json` 125 B: about 1.4 KB per `doc/<ref>` shard, 2.3 MB for all. `version.overview` is 4.8 KB. Datasets (`package_file`): chronology 1.83 MB (duplicate of the list), bundles 1.61 MB, caselines-index 1.19 MB, discovery-schedules 333 KB, quantum 185 KB, lit-prescription 70 KB, lit-recon 35 KB, contradictions 30 KB, timeline-events 25 KB, defence-matrix 19 KB, view-content 13 KB, contracts 10 KB, people 8.6 KB, filings 7.6 KB; every other dataset is under 5 KB (24 keys, 36 KB together). Assets: 1,744 verified originals, 3.25 GB; 1,308 embedded; 2 missing; 7 seed rows.

## 2. Slice families

**A. Shell** (layout, redirects, ViewNav). Shard: `shell.json` = `{ version: {...as above}, caseName, titleName, brand }` built from `version.overview` + `view-content _shell`. Hosted loader: `readCase` + `requireCurrent` (`src/lib/views/hosted/case.server.ts`) then the shard; `isActive` is always true (only the published version is routable), so the candidate banner in `+layout.svelte` never shows. UW: none. Hot files: `+layout.svelte`, `ViewNav.svelte`, `views.ts`.

**B. Read-only dataset views** (15: matter, timeline, contradictions, risk_matrix, vdm_matrix, witness, people, entity_ledger, conflict, elements, legality, quantum_tab, invoice_ledger, prescription, contracts). Every loader is a pure function of (datasets, view-content, `existingRefs`, `documentCounts`, overview, clock). Shard: `view/<id>.json` = **the loader's return value**, built on the operator machine by calling the existing `load` with a fake `parent()`; the Worker never opens a dataset. Hosted loader: one generic `datasetView(id)` that returns `{ ...shard, base }`. Exceptions to carry in the shard: `prescription_tab.asOf` (clock; compute in the Worker), `vdm_matrix_tab.analysisAdditions` (env; false on hosted). UW: none. Payload: 1–185 KB, cacheable with `immutable`.

**C. Document-row views** (chronology + API, documents, search + CSV export, hoa_diff, doc/[ref], and the `files` maps of contracts/filings/bundles). Shards: `list.json` (`ChronologyListRow[]`, 1.5 MB, the only shard every row view needs; `documents`, `search` and `hoa_diff` filter it server-side today, so either the Worker reads it from the Cache API per request or the builder pre-pages: `list/<page>.json` at 60 rows plus `facets.json` for bundle/type/status options), `search.json` (list + `cc`, 1.6 MB; or the FTS index S10 builds), `doc/<ref>.json` = `{ fields, state, attachments (with hasDocument), children, related, parent, assetIds: {own, attachments[]} }` (1.4 KB each, 2.3 MB total). Hosted loader: shard + `AssetsAccess.links`/`availability` for the own original (one call, not one per attachment) + `userWork.notesFor({target: document anchor})`. The chronology `+page.ts` fetch URL must come from server data (`listHref`), not `/api/v/${params.vid}`. UW: `uw_note` R/W on doc only. This family owns the split viewer (iframe of `cases/[caseId]/originals/[assetId]/view`).

**D. User-work registers** (7 registers, info_required, payments, interest_calc and settlement reads, authorities, heads, crossexam, enforcement, filings register, doc notes). Shard: the dataset half of each mixed loader (`view/<id>.json`: filings `groups`+`files`, payments `recon`+`claim`, enforcement steps, crossexam seeds, info items, authorities `imported`, interest basis, settlement). Hosted loader: shard + D1 rows merged by the existing pure functions (`registerEntries`, `crossexamRows`, `enforcementRows`, `infoRows`, `totals`). D1 tables: `uw_register_row` (stores above), `uw_seed_overlay` (`filings`, `lit-crossexam-seed`), `uw_note`, `uw_operation` (idempotency), `uw_case` (revision). Writes go through one adapter (section 4, P4). Payloads tiny; the cost is D1 round trips: `summary` on the overview calls `resolve` per note and `fingerprints` per call (today's `d1-user-work.ts:319-329`), so cap it or precompute `fingerprints` into a shard.

**E. Bundles** (discovery, court, caselines). Shards: `view/<id>.json` from the datasets (court 1.6 MB raw; `bundlesOf` output is what the page needs, so the builder stores the transformed rows and resolved locators), `bundle-paths.json` = `pathIndex` of `documentRows` + `packageFileAssets` → `{ path → {ref|assetKey, presentation} }` replacing `bundleLinks` (today: fs `availability` per package file). `downloads`/`files` hrefs are built by the Worker from asset ids with `AssetsAccess.links`, or deferred to a click on `originals/[assetId]`. UW: `uw_table_row` (`bundles_schedule_mark`, `bundles_custom` via `defineTable`), `uw_register_row` (`discovery-mode`, `bundle-header`, `caselines-links`). `views/bundles/{links,store}.server.ts` are already forbidden in the hosted graph (`scripts/ci/hosted-imports.ts:8`), so this family needs hosted twins of both.

**F. Overview.** Shard `overview.json` = the loader return minus `notes`, `previous`, `slots`; Worker adds `userWork.summary`, the deadlines and unbilled-time tiles from D1 and a `freshness` tile from the publication record (replacing rescan-freshness). The `rollback` action does not exist on hosted.

**G. System** (rescan, backup, manual): drop. Mark `unavailable` for hosted so `ViewNav` greys them and `[category]/[view]` answers with `UnavailableView` (already the fallback route).

## 4. Contract mismatches (`contracts.ts` versus what the loaders need)

1. No shard read. `CaseReader.datasetOf`/`packageFile` fetch one whole package file with a hash per call (`results/hosted/reader.ts:196-208`); timeline needs 6, prescription 3 datasets plus view-content and refs. Need `shard(a: VersionScope & { name: string }): Promise<Response>` (bytes with etag, served through the Cache API), or a separate `PayloadReader` on `RequestServices`.
2. `DocumentRow` has no `attachments`; the local page reads `store.document(...).attachments_json`. The `doc/<ref>` shard must carry them (C above).
3. Original links: local needs `OriginalLinks { presentation, open, download, viewer }` per asset from `assetForServe` + fs `availability`; hosted `AssetsAccess.links` gives three hrefs and no `presentation`, and `availability` is a second call. Derive `presentation` from the shard's `mediaType` and make the doc page do one `links` call, none per attachment.
4. `a.verify`/`verifyVersion` on every page and API call re-hashes the read model; with shards, integrity is the manifest hash recorded at publish (`architecture.md` section 1). Drop `verifyVersion` from the page path.
5. `effectiveActive`/`isActive`, `previousVersion`, `rollback`: hosted has `activeVersionId` and `previousVersion`, no rollback. Overview `previous` becomes "what changed" later; omit now.
6. Notes: local `notesFor(caseId, rv, ref)` and `addNote(caseId, rv, ref, body)`; hosted `notesFor({caseId, target: NoteTarget})` needs an `Anchor` from `anchorFor` first (2 calls), `addNote` needs `operationId` and `expected: absent`. `HostedNote` drops `refAtCreation`/`resultsVersion`/`anchorSha256` that `NoteView` consumers read.
7. Register rows: local `listRows` → `RegisterRow` and `registers(w).open().rows()` computes `version` as a 32-hex sha of fields (`user-work/registers.server.ts:16`); hosted returns `Versioned<WorkRegisterRow>` with a `WorkVersion`. `deleteValue`/`rowVersion` comparisons work with any opaque string, but the stored anchor type differs (`Anchor` with branded ids).
8. Writes: local `putRow(caseId, store, rowId, fields)` throws or returns strings; hosted `putRow({caseId, expected, operationId, store, rowId, fields, anchor})` returns `Written<T>` with `stale|gone`. Forms carry no `operationId` except litigation `addId` and the hosted notes form. `inTurn` serialisation has no hosted equivalent (D1's `uw_batch_guard` + revision does it).
9. Tables: local `defineTable({name, owner, scope, columns, primaryKey})` and `listTableRows(table, {caseId})` return flat rows; hosted `defineTable({definition})` is audited and authorized, `listTableRows({caseId, table})` returns `{cells, version}`, `putTableRow` needs `expected` and `owner`.
10. `seedViews`: local `(caseId, rv, key)` → `SeedView[]`; hosted `({caseId, resultsVersion, datasetKey})` → `Versioned<SeedView>[]`. Compatible after the adapter.
11. `analysisAdditionsEnabled()` reads `process.env`; `now()` and `randomUUID`/`createHash` (`node:crypto`) are used in loaders: fine under `nodejs_compat`, but they must be on the bundle-checker allowlist.
12. `slotStates` loaders are typed over `LocalCase` (`OverviewWidgetLoader<D, LocalCase>`) and discovered by `import.meta.glob` of `*.server.ts`; hosted overview needs loaders over `RequestServices`.
13. Chronology `+page.ts` hardcodes `/api/v/${params.vid}/chronology`; `x-clearcase-degraded` and `failed` providers do not exist on hosted (no providers), so `failed: []`.
