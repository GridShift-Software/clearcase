# Source defects and rewrite defects

Acceptance item 3 asks for source defects to be classified separately from rewrite defects.

- A **source defect** is wrong or risky behavior in the v5 reference itself. It is evidence about the reference, recorded with an ID `S-<view>-<n>`, a severity, line references and a disposition. Parity does not require reproducing it; the owner either corrects it (and records the intentional difference with a `rewrite` expectation) or keeps it visible in the parity report. A source defect is never evidence that a rewrite is correct.
- A **rewrite defect** is a failure of the new implementation against this baseline. At a reviewed revision it is any of: (1) a result that differs from a `source` expectation in [expected-examples.md](expected-examples.md) or a behavior in [view-checklist.md](view-checklist.md) without a recorded intentional difference; (2) reproducing a source defect whose disposition is *correct*, so that a `rewrite` expectation fails; (3) a missing, unresolved or wrongly mapped original, reference or count that the inventory reports as resolvable; (4) user work lost on restart, backup/restore or results activation. No application exists yet, so no rewrite defects are recorded here; gates (CC-23, CC-24, CC-11) record them against an exact revision.
