# 06: TRACER: v5 overview on staging from shards
**Wave:** 1 · **Size:** 1.5 d · **Security-sensitive:** no · **Suggested agent:** strong (Opus / Sol)
## What to build
The operator runs the builder on the converted v5 package on their own machine, uploads the shards with rclone, registers the version in staging's D1, records a human sign-off bound to the shard manifest, and publishes. A colleague signs in on staging, picks the case, and the overview opens in under 2 seconds from the published shards, in the shared shell, with the sidebar showing every other view as coming soon. J1 (shell and navigation) and J2 (overview) pass on staging. Everything later tickets need is in place: a shard reader on `RequestServices`, a hosted version layout returning the local layout's data shape plus `base`, a generic dataset-view loader, list pages and facets, and a builder that picks up one module per shard family from a directory.

How: `research/data-path.md` section 2 steps 2, 4, 5 and `research/view-contracts.md` section 5 (P3). Builder framework in `scripts/publish/`: `cli.ts` (subcommands below), `build.ts` (opens the package through a local import into a temp `CLEARCASE_DATA_DIR` with the existing local service, so `app().store` and the local loaders work; computes `project` and `readModelDigest`; runs every module found by `readdirSync('scripts/publish/shards')`), `manifest.ts`, `sql.ts` (D1 row generation), `signoff.ts`, `publish.ts`. Shard modules this ticket writes: `shards/shell.ts`, `shards/overview.ts` (calls 04's `pure`), `shards/list.ts` (200-row pages plus facets from `listJson`), `shards/originals.ts` (asset id → sha256, size, mediaType, filename, parent, downloadOnly, from the package's assets). Hosted read path: `src/lib/results/hosted/shards.ts` (`ShardReader.read(scope, name)`: cache key `https://shards.clearcase.internal/<clientId>/<caseId>/<rvHex>/<name>`, `caches.default.match`, R2 `get('views/<rvHex>/<name>')` on a miss, `waitUntil(cache.put)`, response headers `cache-control: public, max-age=31536000, immutable`, `etag` = R2 `httpEtag`); `shards: ShardReader` added to `RequestServices` in `contracts.ts`, composed in `services.ts`, with `memory-shards.ts` and `gate/shards.ts` doubles; `CaseReader.publication(scope)` returning `{ versionId, publishedAt, previousVersionId } | null` from `rs_publication` for the version pill. `src/lib/views/hosted/payloads.server.ts`: `shard<T>(locals, params, name)` = `readCase` + `requireCurrent` then the reader; `datasetView(id, isEmpty)` loader factory returning `{ ...shard, base, empty }`. Routes under `deploy/client/routes/cases/[caseId]/v/[version]/`: `+layout.server.ts` (shell shard → `{ version, isActive: true, base, shell: ShellData }`), `+layout.svelte` (`AppShell` + `ViewNav hosted`; `import '$lib/../app.css'`), `+page.server.ts` (303 to overview), `overview/` (shard merged with `userWork.summary` and `src/lib/views/hosted/overview-slots.server.ts`: a `freshness` slot from `publication()`, notes, deadlines `unavailable` until 17a; the wrapper page is `import Page from '$local/overview/+page.svelte'`), `[category]/[view]/` (coming soon through `UnavailableView status="soon"`, 404 for `never`). `src/lib/views/hosted/case-actions.ts` returns the Notes link for the shell's `actions` (19 adds intake). `/cases/[caseId]/+page.server.ts` redirects 303 to the published overview when a version is published, else keeps today's page.

## Decisions already made (don't re-decide)
- Shard prefix: `views/<rvHex>/` in the client bucket, `rvHex` = the results version without `sha256:`. The Worker derives the prefix from the URL; no D1 read for it. Package files are not uploaded; the package stays on the operator machine.
- Names: `shell.json`, `overview.json`, `manifest.json`, `view/<viewId>.json`, `list/page-<n>.json` (n from 1, 200 rows, chronology order), `list/facets.json`, `doc/<ref>.json`, `search/index.json`, `bundle-paths.json`, `originals.json`. Every object is written with `Cache-Control: public, max-age=31536000, immutable`.
- Manifest shape is 04's `PayloadManifest`, canonical JSON, shards sorted by name; its own sha256 is the `shard_manifest_sha256` the sign-off binds. Nothing re-hashes on read.
- Shard modules: one file per family under `scripts/publish/shards/`, default export `{ name: string; build(ctx): Promise<{ name: string; bytes: Uint8Array }[]> }`, discovered by directory scan. No index to append.
- D1 rows written by `register`: `rs_case`, `rs_results_version` (state `stored`, counts, `read_model_sha256`, `overview`, `package_bytes`, `import_seq`), `rs_document`, `rs_asset`, `rs_seed` (yes, still written: notes anchor on document fingerprints and `childDocuments` reads them), and the new `rs_shard_manifest(version_id PK, prefix, manifest_sha256, built_at)`. No `rs_package_file`, no `pub_candidate_*`, no evidence rows.
- Sign-off is a lean new table `pub_version_signoff(version_id, results_version, manifest_sha256, shard_manifest_sha256, validator_version, diagnostics_sha256, acknowledgements_json, signer, signed_at)` in migration 0006 (staging 0008), not `pub_signoff`. Acknowledgements name the fingerprint codes (missing originals, META disagreements, case-mismatch) with a reason each.
- Publication is `rs_publication` in D1, read by the existing `activeVersionId`; no KV pointer. `publish` writes `rs_publication` and keeps `previous_version_id` in one `d1 execute --file` batch. The staged import, evidence engine, readiness rules and render checks are bypassed, not edited.
- CLI: `bun scripts/publish/cli.ts build --package <dir> --case-folder <dir> --case-id v5-demo --out <dir>`; `upload --out <dir> --remote cc-staging:clearcase-staging-files` (rclone with `--header-upload`, then `rclone check`); `register --out <dir> --config deploy/staging/wrangler.jsonc`; `signoff --out <dir> --signer <email> --ack <code>=<reason>...`; `publish --out <dir> --config ...`. `register` refuses a package converted against a partial case folder (any `ASSET_MISSING_AT_BUILD` beyond the acknowledged list).
- `isActive` is always true on hosted; `previous` is null; the `rollback` action does not exist. `slots` always present (spike trap 8). The version pill shows the first 8 hex of the version, `publishedAt` from `publication()` and the document count.
- The hosted folder keeps the param name `[version]`; `params.version` is the results version. Hosted wrapper pages re-export local pages through `$local`.
- Real v5 shards go to staging only; tests use the synthetic fixture (`bun run --bun fixtures:generate`).
