# Native private processed-package import and immutable lineage

**PREPARED/UNVERIFIED component, not a gate, native or Cloudflare PASS.** It follows [ADR-0009](../adr/0009-manual-queue-and-candidate-import-contract.md), [ADR-0010](../adr/0010-exact-version-signoff-and-publication.md), [results-package.md](../results-package.md) and the type contract in [native-integration-contracts.md](../hosted-foundation/native-integration-contracts.md). It grants no permission, adds no policy and publishes nothing. Words follow [GLOSSARY.md](../../GLOSSARY.md).

## What it does

An operator posts a processed results package and names the finalized submission it was made from. The module verifies the package bytes, has the injected real validator and stager stage a **private** candidate, checks the exact required file set against the submission and writes one immutable link. A package that does not map exactly stays private and **unlinked**. A minimal authored correction creates a new candidate and a new link and supersedes the old one.

| Route (`deploy/client/routes/operator/results/[caseId]/…`) | Answers |
| --- | --- |
| `POST imports` | `201` link; `200` the same link again (same actor, operation id and bytes); `422 unlinked` with reasons; refusals below |
| `POST candidates/[candidateId]/corrections` | `201` new candidate and link; `200` repeat; `409 superseded` unless the candidate is current |
| `GET candidates`, `GET candidates/[candidateId]` | the case's candidates and their immutable links, audited, `no-store` |

Request: one strict JSON object read with a hard bound, never a draft route, export or cache. Import: `{operationId, submissionRevisionId, files: {path: UTF-8 text}}` (every package file is canonical JSON). Correction: `{operationId, reason (1 to 500 plain characters), replacements: [{key, data}]}`.

Authority comes before any body byte, row, object or stager call: exact Origin and content type, composed ports, verified identity of this deployment's client, `checkRevocation`, a **staff** principal, then the separate operate capability. Unknown cases and cases without the capability give the same 403 on writes and 404 on reads; only a missing, expired or revoked session is 401. A client principal never reaches a candidate. Every required port is null until the parent composes it (`503 import-unavailable`); there is no default, double or allow-all.

## Lineage (one immutable link per candidate)

The link is the `CandidateImportLink` of `alpha-contracts.ts`: deployment client and case; the finalized submission's `revisionId` and the SHA-256 of its persisted manifest bytes; the candidate instance, supplied `resultsVersion`, exact package `manifestSha256` and the **actual package `inputRevision.id`** (the converter's HTML identity, never a PDF digest); the verified staff operator and server time; `attribution: manual-operator-link-not-processing-proof`. No recipe or processing proof is claimed, no package value is rewritten, an unknown manifest field is refused by the library's own byte verifier, and a package naming another case id is refused (no slug-to-case guess).

- **Coverage `exact-required-file-set/1`.** Every `kind: file` asset (aliases share one fact and keep every ref) maps to a submission file by path, SHA-256 and size. The exact name wins; only when it is absent does a unique case/NFC fold (`foldPath`) match, recorded with both literal paths and the validator's own `ORIG_CASE_MISMATCH` fingerprints copied unchanged. A literal match that carries such a warning, a fold match that lacks one, a warning for an unmapped ref, an ambiguous fold, a sha or size difference, an unmatched required original or any submitted file left unmapped leaves the candidate unlinked. `missing` and `embedded` assets stay explicit and unavailable, with no invented hash.
- **Candidate and link ids** are derived (`cand-`, `link-` plus 32 hex of the canonical JSON digest of their pins), so a retry can only name the same record. A candidate is one per results version; importing it again under another operation, or against another submission revision, is `409 candidate-exists`.
- **Idempotent, actor-bound attempts** (`native_import_attempt`): the same actor, operation and request digest repeats; anything else is `409 operation-reused`, with the same body for another actor.
- **Correction.** Reads the base package back from stored bytes and re-verifies them against the pinned identity, replaces the `data` of existing **authored** datasets only (generated datasets, the asset index and every other file keep their bytes), sets `parent` to the base version and `created` to the correction time, computes the new `resultsVersion` with the library formula, and runs the same stager, submission re-check (`storedManifestSha256` must still equal the link's) and exact-set policy. It records who, when, the reason and each changed file's before and after sha256 and size; the old candidate becomes `current: false, supersededBy`, which is what an exact-version sign-off must check. Originals, user work and the old stored version are untouched.
- **Schema** `migrations/0001_native_candidate_import.sql`: five `native_*` tables, `BEFORE INSERT` triggers that refuse a collision on any unique key (so `INSERT OR REPLACE` cannot reach a row), cross-checks (a link names its candidate, attempt operator and submission revision; a correction names a current linked parent) and refused `UPDATE`/`DELETE`. A link also stores the digest of its canonical form; a read recomputes it and answers `503 integrity` on mismatch.

## Parent integration handoffs (none applied here)

1. **Compose** with `setNativeImportComposition`: `clientId`, `nativeImportBudget(env…, {stagerMaxPackageBytes})`, `authorizeOperate` adapted from GRS-114's `operate` capability, `submissions: submissionSnapshotReader(d1SubmissionRepository(DB))`, `repository: d1NativeCandidateRepository(DB)`, `stager`, `packages` (corrections only; null keeps them 503), `audit` (the GRS-116 request sink). Add `NATIVE_IMPORT_MIGRATIONS` to the client's Wrangler migrations and `tests/results-review/native/**/*.test.ts` to the root Vitest include. Typed APIs: `createNativeResultsImport`, `createCandidateReader`.
2. **Stager (parent).** Must run the real validator over trusted per-case facts and store the version privately (GRS-115 `ResultsStaging`, with its verified original facts), and return the identity it staged plus every `ORIG_CASE_MISMATCH` diagnostic `{ref, fingerprint}`. This module re-checks the identity against the bytes and never trusts a stager that disagrees.
3. **Manifest bytes.** The intake stores manifest rows, not bytes; `submissionSnapshotReader` hashes the library's canonical text of the stored manifest (`finalizedAt` is reserve time and is unchanged). If the parent wants byte-persisted manifests, the intake changes, not this link.
4. **Sign-off** (parent): bind `ImportLinkSignoffBinding` and refuse a candidate with `current: false`. Publication, private preview and the audit-before-visibility rules are not here.
5. **Audit.** Success appends one idempotent event per (link, session) after the commit; a fault answers 503 and a retry completes. Refusals append best-effort. A crash between commit and append leaves a link with a missing event until the retry; audit durability is unverified here.
6. **Hosted hashing.** Own digests use Web Crypto and the library's browser-safe canonical JSON; package formulas are not reimplemented, they come from `verifyCandidateBytes`, `resultsVersionOf` and `sha256Hex` (`node:crypto`, which the import guard allows and the hosted staging already uses).
